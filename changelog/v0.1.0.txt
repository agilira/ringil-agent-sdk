v0.1.0 — unreleased

First increments of the SDK core: data model and providers (N1), tool API
(N2), agent loop (N3, base) and sessions (N4), with the ringil CLI.

FEATURES

  - Data model owned by the SDK: Message with parts, ToolCall, ToolResult,
    Usage, StopReason, ToolSpec with annotations. No vendor wire type
    crosses the provider boundary.
  - Provider contract: one Generate method with an explicit TextSink for
    streaming; tool calls are assembled by the adapter and returned whole.
  - Error codes for every provider failure (auth, rate, unavailable,
    context, input, response, interrupted) with Retry-After support.
  - provider/openai: any OpenAI-compatible server. Streaming and plain
    calls, tool calls (indexed or not), usage with cached tokens, broken
    model JSON reported as BadInput instead of failing the call, missing
    call IDs generated.
  - provider/retry: retries rate limits, server errors and cut streams with
    jittered backoff; honours Retry-After; never repeats text already shown
    unless the host handles OnRestart.
  - provider/budget: call and token caps shared by several providers; a
    call is counted before it is sent, the call that crosses the token cap
    is delivered and the next is refused.
  - provider/ratelimit: requests per minute with burst, and a cap on calls
    in flight; shared across providers on the same quota.
  - provider/circuit: opens after consecutive server failures, fails fast
    with a retryable CIRCUIT_OPEN carrying the wait, one probe at a time;
    refused requests, bad keys and cancelled calls do not count.
  - provider/fake: scripted provider for tests.

  - NewTool: tools from typed Go functions. JSON schema generated from the
    input struct (json, desc, enum, min, max tags); the same compiled schema
    drives validation, so what the model is told and what is enforced
    cannot drift. Output: string, ToolOutput, or JSON for anything else.
  - Tool interface for tools with runtime schemas (MCP, generated tools).
  - Registry: immutable, sorted specs, With and Select for worker subsets,
    Execute returning the model-facing result and the full host error.
  - ToolError and ModelMessage: a tool decides what the model may read.
  - Agent loop: model, tools, results, until the model answers. Stream
    yields typed events (text, model, tool start/end, recovered, done) as an
    iterator; breaking out cancels the run. MaxTurns optional, default none.
  - Conversation interface; every message is recorded as soon as it exists,
    the model's tool calls before any tool runs.
  - Interrupted runs: unanswered calls are reported to the model as
    interrupted and never executed again; StrictResume refuses instead.
  - session/file: append-only JSON Lines with a SHA-256 hash chain, one
    file per session, exclusive lock, partial last line cut after a crash,
    no length limit. In-memory conversations with NewConversation.
  - cmd/ringil: chat and one-shot run on any OpenAI-compatible endpoint,
    streaming, built-in read-only tools (now, calculate), saved sessions
    (--session, sessions, sessions rm).
  - skills.InstallGitHub and the install_skill tool: install a skill from
    a GitHub link the user gives (a repository, a folder, a SKILL.md, its
    raw.githubusercontent.com link, or owner/repo/folder@ref). The ref is resolved to its commit and that
    archive installed; a folder with several skills is refused with their
    links, for the user to pick one. The source is recorded in the
    manifest (Catalog.Source).
  - LiveRegistry: tools the host changes while the agent runs. A run takes
    the tools of the moment before each model call, rebuilding the
    tool_search catalog when they changed; the calls of a turn run on the
    tools the model was shown. Catalog.Reload reads the skills again.
    Together: what install_skill and add_mcp_server install works in the
    same conversation, at the next model call.
  - channel/slack: a Slack app in Socket Mode (no public address). Direct
    messages, and threads in channels (a mention starts one, a thread the
    bot is in needs no mention); buttons for approvals; the app's slash
    command as the Bridge's commands; files from files.slack.com; 👀 on
    the message being answered. The agent's markdown goes as a markdown
    block that cannot ping (<!here>, <@U…> defused); the Bridge's texts
    as plain text. docs/slack/manifest.json creates the app.
  - dirs: the standard places of a program on each system (configuration,
    state, data), kept apart even when the XDG variables coincide.
  - Defaults for a host that sets nothing, as coding agents behave: the
    Bridge's inbox in the program's data, its sessions and shared phones
    in its state; serve keeps conversations in files (NoStore for none);
    bash and the file tools never reach the program's own places; skill
    scripts run in this system's sandbox and keep their files in the
    program's data, with a 5 GiB quota; an MCP sign-in is kept per server;
    workflows keep a journal; a group with no members' or public profile
    talks with the owners' profile, answering the owners only. An inbox
    inside the agent's own places is refused at once.
  - mcp.Entry, mcp.AddFunc and the add_mcp_server tool: the agent adds the
    MCP server the user asked for, read from its documentation; the host
    saves and connects it (Adder) and reports its tools and the secrets
    still to set.
  - price: the cost of every model call in US dollars (Usage.Cost). No
    price is in the code: Catalog downloads OpenRouter's public list (every
    vendor it serves), keeps it on disk a day and falls back to the saved
    copy; Table.Over puts the host's prices on top. Cache reads and writes
    and long-prompt tiers priced apart; names found as each provider spells
    them. The cost reaches events, results, workers' reports, the
    workflows' journal, the event log and the metrics
    (ringil_cost_usd_total). openai.Config.StatesCost takes the cost an API
    states (OpenRouter); OpenAI cache writes read from usage.
  - Dollar limits: Config.MaxCost stops a run cleanly (StopMaxCost),
    budget.Limits.Cost refuses calls past it (BUDGET_COST, Unpriced counts
    calls with no price), workflow.Budget.Cost.
  - provider/fallback: the next model answers when a provider does not
    (down, rate limited, cut or malformed answer, key refused, circuit
    open), at once; the failed one is passed over for a cooldown that
    doubles, then tried again. Request errors stay; streamed text is never
    repeated (OnRestart); OnSwitch tells which model answers. One provider
    is returned as it is.
  - document and the read_document tool: the text of Word, Excel,
    PowerPoint and OpenDocument files with the standard library alone,
    in reading order (sheets with rows and cell columns, slides in their
    order, table cells by " | "), read in pages like read_file and under
    its policy. Bounded against zip bombs, repeated cells and deep XML;
    password-protected and old binary files named as such.
  - PDF in read_document, page by page (github.com/agilira/pdf, a fork of
    ledongthuc/pdf): a page without text is named a scan, a damaged file
    is an error, never a panic. The fork bounds five reference cycles that
    looped forever or overflowed the stack on a crafted file; the fix is
    proposed upstream (ledongthuc/pdf#109).
  - PartDocument: a PDF travels where images do (a tool's result, a
    user's message), checked by CheckDocument (a PDF by its bytes, at most
    32 MiB), counted with images (kept for the latest turns, a note
    after), costed by its size in compaction. Claude reads it as a
    document; openai.Config.Documents sends it as a file (OpenAI,
    OpenRouter); other models and the ChatGPT subscription are told a PDF
    is there. read_document attaches the PDF when pages have no text.
  - otel: each run as an OpenTelemetry trace by the GenAI conventions:
    invoke_agent, chat (model, tokens, cache, ringil.usage.cost_usd) and
    execute_tool spans, a worker's run under the call that started it,
    errors by code. Metadata only, as eventlog (whose rules it reuses,
    now exported: Code, ToolName, CallID, Stop, Note). The OpenTelemetry
    API only; Event.Model names the model that answered, Event.ParentCall
    (and agent.ToolCallID) the call that started a delegated run, so a
    worker's span goes under its own call when several run at once.
  - ringil: traces over OTLP/HTTP with the standard OTEL_EXPORTER_OTLP_*
    variables, flushed at exit. Each revision of ringil.yaml is a
    ringil.config span too (loaded, applied, refused): its digest, the one
    before, the keys that changed and what needs serve restarted; never a
    value, and a refusal by its code only.

SECURITY

  - HTTPS required except towards loopback; AllowHTTP for LAN and pods.
  - Redirects never followed, so the key and the prompt cannot be sent to
    a host nobody configured.
  - Upstream error bodies never returned; reserved headers cannot be
    overridden; control characters refused in keys and headers.
  - Bounds on every untrusted byte stream (lines, events, bodies, number of
    tool calls), far above real use; stalled streams are cut.
  - Tool arguments validated before the function runs: unknown fields
    (including case variants encoding/json would accept), wrong types,
    integer overflow, non-finite numbers, enums, ranges, required fields.
  - Validation feedback names schema fields only: values sent by the
    model, unknown field names and unknown tool names are never echoed.
  - Undescribed tool errors reach the model as a code only; panics in
    tools are recovered and their value goes to the host only.
  - Registered specs are frozen copies; tools receive a copy of their
    input; Select can only narrow a registry.
  - Tool arguments are validated, then the re-encoded validated form is
    decoded: duplicate JSON keys cannot carry values past the schema.
  - Session files: IDs restricted to [A-Za-z0-9_-], all access through
    os.Root, symlinks refused, 0600 files in a 0700 directory, damaged or
    edited lines reported as SESSION_CORRUPT.
  - The CLI strips terminal control sequences from model and tool output.
  - install_skill and add_mcp_server are destructive: the default policy
    asks. Unpacking a skill stays in its folder (no "..", absolute path,
    drive, colon or link) within bounds of download, files and bytes.
    An MCP entry that does not print in full is refused, a remote one is
    HTTPS, and a header holds a secret only as ${NAME}.
  - Fuzz targets for GitHub links and MCP entries.
  - Fuzz targets for the SSE decoder, the response parser, the argument
    validator, typed tool calls and the session file loader.
