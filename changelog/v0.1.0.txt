v0.1.0 — unreleased

First increments of the SDK core: data model and providers (N1), tool API
(N2).

FEATURES

  - Data model owned by the SDK: Message with parts, ToolCall, ToolResult,
    Usage, StopReason, ToolSpec with annotations. No vendor wire type
    crosses the provider boundary.
  - Provider contract: one Generate method with an explicit TextSink for
    streaming; tool calls are assembled by the adapter and returned whole.
  - Error codes for every provider failure (auth, rate, unavailable,
    context, input, response, interrupted) with Retry-After support.
  - provider/openai: any OpenAI-compatible server. Streaming and plain
    calls, tool calls (indexed or not), usage with cached tokens, broken
    model JSON reported as BadInput instead of failing the call, missing
    call IDs generated.
  - provider/retry: retries rate limits, server errors and cut streams with
    jittered backoff; honours Retry-After; never repeats text already shown
    unless the host handles OnRestart.
  - provider/budget: call and token caps shared by several providers; a
    call is counted before it is sent, the call that crosses the token cap
    is delivered and the next is refused.
  - provider/ratelimit: requests per minute with burst, and a cap on calls
    in flight; shared across providers on the same quota.
  - provider/circuit: opens after consecutive server failures, fails fast
    with a retryable CIRCUIT_OPEN carrying the wait, one probe at a time;
    refused requests, bad keys and cancelled calls do not count.
  - provider/fake: scripted provider for tests.

  - NewTool: tools from typed Go functions. JSON schema generated from the
    input struct (json, desc, enum, min, max tags); the same compiled schema
    drives validation, so what the model is told and what is enforced
    cannot drift. Output: string, ToolOutput, or JSON for anything else.
  - Tool interface for tools with runtime schemas (MCP, generated tools).
  - Registry: immutable, sorted specs, With and Select for worker subsets,
    Execute returning the model-facing result and the full host error.
  - ToolError and ModelMessage: a tool decides what the model may read.

SECURITY

  - HTTPS required except towards loopback; AllowHTTP for LAN and pods.
  - Redirects never followed, so the key and the prompt cannot be sent to
    a host nobody configured.
  - Upstream error bodies never returned; reserved headers cannot be
    overridden; control characters refused in keys and headers.
  - Bounds on every untrusted byte stream (lines, events, bodies, number of
    tool calls), far above real use; stalled streams are cut.
  - Tool arguments validated before the function runs: unknown fields
    (including case variants encoding/json would accept), wrong types,
    integer overflow, non-finite numbers, enums, ranges, required fields.
  - Validation feedback names schema fields only: values sent by the
    model, unknown field names and unknown tool names are never echoed.
  - Undescribed tool errors reach the model as a code only; panics in
    tools are recovered and their value goes to the host only.
  - Registered specs are frozen copies; tools receive a copy of their
    input; Select can only narrow a registry.
  - Fuzz targets for the SSE decoder, the response parser, the argument
    validator and typed tool calls.
